# ДДС, банки, дълготрайни активи

## ДДС

### Дневници

`GET /v1/vat/registers?period=YYYY-MM` дава дневниците покупки и продажби за
периода. Източникът е дневникът на активната фирма; ставките идват от редовете
на фактурата. Ръчен запис без фактура се изчислява на 20% или без ДДС.

`GET /v1/vat/return` — данъчният материал с клетките на декларацията
(01-01 … 01-82).  Rъчните клетки (33, 70, 71, 80, 81, 82) се въвеждат с
`PUT /v1/vat/manual`.

Протоколът по чл. 117 влиза в двата дневника и се нулира; кредитните обръщат
знака веднъж.

### Файлове за НАП

`GET /v1/vat/export?period=YYYY-MM&kind=…`:

| `kind` | Файл |
|--------|------|
| `deklar` | `DEKLAR.TXT` |
| `pokupki` | `POKUPKI.TXT` |
| `prodagbi` / `prodajbi` | `PRODAGBI.TXT` |
| `vies` | `VIES_YYYYMM.TXT` |
| `zip` | `PPDDS_YYYYMM.zip` (трите файла, ZIP без компресия) |

Формат: Windows-1251, фиксирана ширина, CRLF. `VIES_YYYYMM.TXT` носи данните за
ВОД, тристранни и услуги по чл. 21.

Основанията за неначисляване са в каталога VATEX (`GET /v1/vat-exemptions`).

## Банки

### Сметки

`bank_accounts` на фирма: IBAN (уникален), BIC, име на банка, валута, ГЛ сметка
и буферна сметка. Салдото е низ с два знака.

### Импорт на извлечения

`POST /v1/bank-transactions/preview` разпознава формата и показва какво ще
вляезне; `POST …/import` записва. Поддържани формати:

- CSV;
- MT940;
- XML на Postbank, UniCredit, OBB;
- ISO camt.053.

Дубликатите се разпознават по референция. Автоматичният запис е **Дт ГЛ сметка /
Кт буферна сметка**.

### Разнасяне

- ръчно осчетоводяване (`book`) и разнасяне (`reallocate`);
- правила (`bank_matching_rules`) с ключови думи (кирилица → латиница),
  посока, приоритет и шаблон за сметка/контрагент;
- автоматично разнасяне с преглед (`auto-allocate/preview` и `auto-allocate`).

## Дълготрайни активи

### Категории

`fixed_asset_categories`: име, СИТА категория, минимална и максимална норма,
метод по подразбиране, сметки за актив, амортизация и разход.

### Активи

`fixed_assets`: инвентарен номер, категория, дати на придобиване и въвеждане в
експлоатация, цена, ликвидна стойност, полезен живот в месеци, метод
(`linear` / `declining`), счетоводна и данъчна норма, натрупана амортизация по
двете оценки, статус, консервация, обект.

### Амортизация

`POST /v1/fixed-assets/depreciation/preview` показва записите, `…/post` ги
създава. Един запис: **Дт 603** (разход за амортизации) / **Кт 241** (амортизация
на ДМА). Липсващите сметки 603/241 дават грешка.

### Събития

`revalue` (преоценка), `move` (местене), `conserve` / `end-conserve`
(консервация), `dispose` (отписване). Всички се записват в `fixed_asset_events`
с дата, сума и предишна стойност; историята е на `GET /v1/fixed-assets/:id/events`.
